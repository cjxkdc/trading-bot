# 账户表现、监控与统一调仓计划

## 日常入口

- **账户 → 账户总览**：净资产、现金、持仓盈亏、分区间投资收益与持仓明细。首次没有历史时点击「刷新账户」，或等待后台监控取得第一条记录。资金流水与调仓复盘折叠在下方。
- **账户 → 持仓与订单**：实际持仓及本程序的订单，显示冻结订单或券商账本提供的历史股票代码。
- **系统 → 监控与通知**：账户检查频率、通知渠道、故障与恢复事件、可选外部心跳。任务诊断在「运行与日志」。
- **策略运行 → 单策略计划 → 调仓设置**：每日／每周／每月、执行时间，以及首次建仓立即开始或遵循计划。QuantConnect 导出会冻结同一份计划；之后修改自动运行计划，不会修改已经导出的实验。

## 账户统计

当前 Futu、moomoo 的美股模拟账户支持此接口。其他券商模块可以实现 `financial_account_reference()` 和 `financial_observation()` 并声明 `observe` 能力；Portal 不依赖具体券商名称。

净资产使用券商报告的 `total_assets`，与现金、下单可用资金分开展示。监控仅查询已绑定的模拟账户，允许存在挂单；不会授予交易权限、交易解锁、提交或撤销订单。

部分美股模拟账户的资金币种字段返回 `N/A`。仅当券商账户列表已核验为美股单市场模拟股票账户时，才按 USD 解释；其他币种或混合市场账户不作此推断。依据：[moomoo 账户资金接口](https://openapi.moomoo.com/moomoo-api-doc/en/trade/get-funds.html)。

历史从启用记录开始，不能据此恢复之前的收益。收益统计取每日最后一个观测点，并保留统计起点、重置后的第一个点及最后已核对的精确观测；没有收盘观测时，不代表精确收盘价。未知费用、成本或估值显示为空，不算作零。当前仅接收 USD 账户及受支持的美股多头持仓，混合币种或不支持的仓位会明确阻止统计，保留之前的历史。

区间可选近一周、近一月、近三月、今年和全部；均按美东时间筛选，月份采用日历月。每个区间以范围内的第一个实际记录为基准，显示实际起止日期，不补造区间边界价格。净资产、投资收益率、投资盈亏金额可以切换，图表支持悬停、键盘方向键与数值表。

持仓表显示名称、数量、现价、券商成本、市值、权重和券商持仓盈亏，可搜索、按市值／盈亏／权重排序。OpenD 的 `pl_val` 与 `pl_ratio` 只有有效标志为真时才使用；比例除以 100 转为内部小数。证券模拟盘不提供标准已实现／未实现盈亏拆分，因此不将 `pl_val` 命名为未实现盈亏。任何持仓盈亏缺失时，总持仓盈亏也显示「—」。旧历史记录不会被重新解释；新采样后才有这些字段。依据：[Futu 持仓接口](https://openapi.futunn.com/futu-api-doc/en/trade/get-position-list.html)。

## 净资产 K 线

「账户 → 账户总览 → K 线」可切换 **1 分钟、5 分钟、小时、日、周 K**。图表使用数据库中实际保存的每次账户观测，开／收为周期内最早／最晚的净资产，高／低为其中的最大／最小值，不是从每日收盘值倒推出盘中变化。既有观测可以直接使用，无需重新下载历史行情。

日 K 按美东自然日，周 K 按美东周一至周日；小时按真实经过的时间划分，夏令时重复的两个小时分开保存。默认显示最近 96 个周期，空缺周期留空，周期内只有一个点时显示横线。未结束的周期标记「形成中」。鼠标悬停、键盘方向键或「查看数值」可检查各根 K 线的数值及观测点数。

这些高低值只代表**采样中实际看见的净资产**，不保证覆盖采样间隔之间的真实波动。每小时采一次无法形成完整的小时内高低点；每分钟采一次也不能恢复分钟内波动。净资产包含出入金、分红及费用，与扣除出入金后的收益率不同。账户重置开启新的图表区间，账户切换不会混用记录。

净资产涨跌可能包含出入金。若需要投资收益，在「资金流水与收益核对」补记该期间的转入、转出或账户重置，再确认核对至最新观测。投资盈亏金额 = 期末净资产 − 期初净资产 − 净入金。收益率采用按观测区间连接的 Modified Dietz 估算；转入转出按时间加权扣除，分红和费用已体现在净资产中，不再重复扣减。录错可删除重记。新增观测后需要核对新期间；未核对的尾段只显示净资产，已核对区间的收益和回撤保留并注明截止时间。修改资金记录会使原核对失效；仅一个观测点不会显示已计算区间收益。

回撤依据记录点，可能遗漏盘中下跌。重置开启新的测量区间。可选基准由数据模块提供，当前 Massive 使用拆股调整后的价格，不含股息再投资；只比较与账户记录相匹配的已结束交易日，并显示比较区间。基准不可用不会阻止账户记录或交易。

调仓复盘仅覆盖本程序产生的记录；订单被接受不等于成交。当前权重仅与最近一次完成的执行目标比较，研究预览不会覆盖它。部分成交或结果待核对时，以订单核对及券商记录为准。

## 监控和通知

账户监控默认每 15 分钟查询一次，可在「系统 → 监控与通知 → 采集间隔」选择 1、5、15、30 或 60 分钟；升级保留已有设置。间隔是目标频率，网络请求、下载或交易任务可能延后采集。更频繁的采集会增加接口调用与本地历史存储，后台停止期间不补造记录。

监控与自动调仓开关独立。关闭自动调仓后继续监控；停止整个后台则暂停监控。断开当前账户会关闭账户监控，重新绑定后可在「系统 → 监控与通知」启用。检查任务与交易共用互斥工作队列，交易或下载未结束时等待，不并发操作账户。

默认只在面板保存事件。外部通知目前提供 Telegram，可在通知模块注册其他渠道，面板从渠道声明读取配置字段。使用自己的 Bot Token 和 Chat ID，保存后点击发送测试通知；凭据留空保留已有值，不会返回浏览器或进入发布包。通知包括任务结果、执行异常、账户故障和恢复，不包含账户号、余额或持仓详情。同一故障状态不会每次轮询重复发送；每条消息最多尝试三次。网络超时可能导致重复送达，面板显示送达、失败或等待状态。

整个 AWS 实例停机时，实例内的程序也无法发告警。可自行创建 Healthchecks 检查，在它的设置里配置 1 分钟周期、至少 5 分钟宽限和接收通知方式，然后把该检查的 `https://hc-ping.com/<UUID>` 地址填入外部心跳。后台每分钟发送不含账户数据的存活请求；是否告警由外部服务的配置决定。此心跳表示工作台监控循环在运行，不证明交易或券商登录正常。

事件与财务记录位于 `runs/monitor/` 的独立 SQLite 文件，通知配置位于 `secrets/notifications/connection.json`。它们不进入 Git 或发布包；备份时保留整个 `runs/` 和受保护的 `secrets/`。

## 回测与运行的边界

同一计划包括周期、日期、时间、执行窗口和首次建仓规则，策略参数仍由策略模块控制。回测和自动运行都按交易日历处理节假日；超过执行窗口不会补交过期计划。

共用计划不等于收益完全可比：QC 使用其历史数据、成交模型及市场单；当前模拟运行使用配置的数据源及券商 DAY 限价单。数据调整、股息、手续费、滑点与成交时序仍可能不同。实验清单记录计划与执行模型；应在相同假设下比较结果，不能把页面曲线直接当作 QC 回测复现。
