# 策略运行

策略库保存可替换的 Python 插件；「策略运行」保存插件的运行实例。一个插件可创建多份实例，每份拥有自己的名称、参数、账户资金比例、数据源和调仓计划。联网模拟和实盘账户使用相同实例模型；实盘可以先保存配置，启动前必须取得具体账户的服务器执行授权。市场、币种、交易单位与日历由模块提供，详见 [模块化交易执行](MODULAR_EXECUTION.md)。

## 开始使用

1. 在「连接」中配置自己的账户和数据源，核对模块支持的市场、订单能力和账户环境。
2. 打开「策略运行」，创建实例，选择策略、账户、数据源及资金比例，保存。
3. 可先「检查连接」及「预览选股」。预览只读取与实例数据需求匹配的已有快照，不连接券商、不更新数据；休市时也可运行。首次使用或修改数据需求后，先在数据中心选择相应策略更新数据。预览显示数据日期、候选数量、策略内权重和折算到账户后的权重。
4. 「启动」会立即检查前置条件，在指定交易窗口建仓，之后按每日、每周或每月计划调仓。数据更新时间和执行窗口使用实例保存的 IANA 时区，新建时取账户模块默认值；按模块提供的真实交易区间处理夏令时、休市、午休及提前收盘。未获执行授权的账户保留配置，但不能启动。
5. 「执行一轮」对停止的实例运行一次，休市时等待下个可用窗口，完成后停止。已运行的实例执行后继续自己的计划。
6. 「详情与日志」显示最近选股预览、实际确认后的归属股数、参数和记录；也可按此实例的参数及计划导出 QuantConnect 回测代码。

选股预览不包含实时价格、下单股数或订单授权；执行时重新核对数据和券商报价，按标的的数量步长、最低数量、报价步长和乘数计算订单。修改参数、代码或确认持仓后，旧预览不再显示；最新一次预览失败时也不会显示此前的成功结果。单次连接检查或预览失败不会停止正在运行的实例；账户执行发生异常时，只暂停相关账户。

创建和保存不会开启交易，模拟账户也不会因切换环境而变成实盘；账户环境与真实绑定必须匹配。关闭网页不停止后台；停止后台或关闭服务时无法执行计划。服务器上的实例在服务重启后继续等待计划，未完成的账户批次会暂停，要求先核对，不会静默重发订单。

## 多策略共用账户

资金比例按整个账户净值分配，例如 60% MOM8 + 40% 科技股策略；比例总和不能超过 100%。策略本身的仓位仍受保存的风险配置限制，例如某策略配置投入其资金的 95% 时，60% 的账户预算对应最多 57% 的股票目标；95% 是配置示例。

页面按账户显示已预留和可分配的资金比例。运行实例和停止但保留持仓的实例均占用分配比例；无持仓的停止实例不占用。这是配置中的资金预算，不是券商现金或购买力。保留持仓时修改预算也会检查总额，避免超过 100%。同一账户本轮内，使用相同数据源、范围、字段、历史长度及采集规则的实例共用一次数据更新；数据需求不同则分别采集。

框架只重算本轮到期实例；其他实例保留已确认的原数量，包括模块支持的小数数量。同一标的的多个目标先合并，再向券商提交账户净差额。券商显示合并持仓，内部账本记录归属，确认成交后才更新。账户中原有的其他持仓单独保留，不自动卖出；这些持仓仍可能使合并目标超过账户总仓位或单股上限，此时暂停并显示原因。

停止实例会保留持仓，也保留其资金比例。已提交的订单继续核对；停止会阻止后续新委托，不会自动撤单或平仓。保留持仓的实例不能删除或更换账户。要退出持仓，应先把此实例策略调整为能够返回现金目标的规则，按计划执行并确认退出后再删除；不会把「停止」解释为清仓。

一个账户由策略实例管理后，旧的单策略自动计划和手动提交入口不能同时用于该账户。多个配置指向同一账户时，应统一使用一个账户配置。归属股数出现非预期减少、账户变化或配置变化时暂停；不要手动修改 `runs/strategy_manager/state.json` 来跳过核对。

## 估值与收益归因

运行详情里的「估值与收益归因」把实例在共享账户里的归属股数换算成市值和盈亏（`GET /api/strategy-instances/<id>/attribution`，逻辑在 `app/instance_attribution.py`）：每轮调仓后的归属股数变化，若同一轮账户对该标的有成交，按成交均价计价；没有对应成交的变化（持仓在实例之间转移）按当时的账户观测价计价；两者都没有则标为「无价格」并提示。市值按账户监控的每日最后一次观测（`runs/monitor/performance.sqlite`）里的最新价计算，不含现金；盈亏 = 市值 − 投入成本。只覆盖保留的运行记录（`runs/strategy_manager/logs/`，受「计算与日志限制」里的保留轮数约束）与账户观测，记录被清理后更早的成本不再计入；没有开启账户监控的账户只能看到股数变化，没有市值。

## 中断后的核对

「核对订单与归属」只查询已提交订单，不提交新的委托。若批次中仍有从未提交的订单，先停止此账户全部实例，再使用「结束未提交余单」；核对成交后按实际持仓分配归属，结束剩余计划。已有委托未确认时继续暂停。结束后的实际组合不一定达到原目标。若核对发现委托已被券商撤销或拒绝，在「连接检查与维护」中使用「关闭已撤单/拒单」：程序重新查询券商确认状态后关闭这些委托，按实际持仓更新归属，并保留审计记录。

发送前的检查失败（券商查询超时、账户仍有未完成委托、现金或可卖数量与预检不符）不会把委托记为「已拒绝」：委托退回「待提交」，核对后可以在同一批次内继续执行；只有静态校验（代码格式、整股、金额上限）失败才记为发送前拒绝。状态不明且没有券商回执的委托，可在手动调仓或单策略计划的订单核对中用「确认未发送并关闭」处理，见 README。

## 策略文件

「策略」采用左侧策略库、右侧工作区。选中策略后，切换「策略说明／参数／Python 代码／研究／运行」，直接在页面中编辑；左侧导入 ZIP，右上角导出所选策略包。ZIP 根目录包含：

```
strategy.py      # 实现 select(stocks) 或 select_with_context(stocks, context)
manifest.json    # type、kind=portfolio、entrypoint、输入 schema、数据需求等
README.md        # 可选，在「策略说明」中展示
```

「Python 代码」中的嵌入式编辑器支持行号、语法高亮、自动缩进、代码折叠、搜索替换和撤销重做；Ctrl / ⌘ S 保存，Ctrl / ⌘ F 搜索。Tab 缩进；在编辑区按 Esc 后再按 Tab 可移出焦点。编辑器按需加载，不影响首页加载。切换策略、栏目或重新登录时，代码草稿保留在当前浏览器标签页内存中，并保留原文件版本以防覆盖外部修改；不会写进浏览器本地存储。刷新或关闭浏览器会提示，但真正离开后草稿不保留。可先下载 .py 留存；「重新载入」丢弃草稿前会确认。

选择策略只改变查看对象，不会切换运行策略。参数页的「保存策略配置」才会更新手动调仓与单策略计划的默认配置；运行实例仍保留各自参数。参数草稿保留修改时的配置版本，检测到外部变更时要求重新核对。

建议下载现有包作为模板，修改 `manifest.json` 的唯一 `type`，保留匹配的类名和接口。上传会使用独立模块名，不覆盖原插件。编辑前停止全部自动计划和实例，并处理未完成批次；运行期间可以只读查看和复制代码。保存时验证 Python 可编译性、登记类名及文件版本，原代码备份在 `runs/strategy_manager/source-history/`。此检查不会执行代码，也不能代替回测或运行检查。上传、编辑仅限已登录的工作台主人。

Python 插件具有程序用户的权限，只使用自己编写或审查过的代码。计算进程的时限和资源限制用于防止意外卡住，不是隔离恶意代码的安全沙箱。通用任意脚本、独立无限循环或自带下单函数不属于这个插件接口。

## 计算、日志及回测边界

每次实例选股在独立子进程运行，默认 60 秒，面板可调为 10–120 秒；输入上限 32 MB。Linux 增加 768 MB 地址空间及 60 秒 CPU 上限；Windows 使用计算超时和输入上限。涉及委托的执行进程不会因选股超时被强制结束。

最多管理 16 份实例。面板可保留最近 20–500 轮执行日志；账户意图账本、持仓归属和批次审计文件不会随日志清理。`runs/strategy_manager/` 为私有运行状态，不打包或上传 GitHub。

当前通用执行模型是现金覆盖、只做多、限价调仓；现有组合策略输入采用日线快照。共享账户的一次净额批次要求市场、币种和订单语义一致；没有明确换汇模型时，不会混合不同币种的报价计算目标。新增市场、券商或盘中策略需要实现相应模块及契约，不能仅修改名称宣称支持。

现有 QC 适配器支持已声明的日线美股输入，不支持的市场或时区会明确拒绝导出。QC 导出单独回测该实例的策略与计划，不模拟其他实例对现金和账户的影响。账户级表现从「账户总览」中的实际净值记录观察；每个实例目前显示股数归属和执行记录，没有独立收益曲线。独立实例收益归因及多策略组合回测尚未实现。
