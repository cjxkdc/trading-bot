# 五模块结构与运行方式

## 依赖关系

```text
configs/portfolio_config.json + configs/data_sources.json
                      ↓
                  app/assembly.py                 装配入口
                 /     |     \
               data strategies brokers
                 \     |     /
                   framework                  公共契约与运行
                      ↑
                   backtests                  历史数据、时钟、撮合与报告

数据适配器 → 标准快照 → 策略 → 目标持仓
                                  ↓
                         框架检查 / 仓位计划
                                  ↓
                          订单账本 → 券商适配器
```

- 框架不导入具体策略或平台。数据结构、策略接口、订单接口均定义在框架中。
- 策略只依赖标准数据类型；同一输入、同一参数应产生相同目标。
- 数据模块负责获取、校验、缓存和标准化；券商模块负责账户与订单，两者互不依赖。
- 装配入口读取策略、数据与券商的登记文件，检查输入格式，并注入依赖。
- 回测复用策略规则和公共决策契约，更换数据、时钟、撮合；结果不等同于真实成交。

## 策略模式

`PortfolioEngine` 接收实现 `PortfolioStrategy` 的对象。`PortfolioRunner` 使用同一个决策函数进行预览和本地执行。策略可以替换，框架按统一的目标权重工作。

组合策略声明 `history_requirements`，由历史数据接入读取足够的已完成日线。盈利和排名筛选只存在于策略模块中。当前 QC 接入按策略声明支持科技板块股票池和 MOM8 的全美股普通股池；换成期权等新资产类型时还需新的数据契约/适配器。

`strategies/plugins/` 声明策略名称、类、版本和输入格式。`data/plugins/` 和 `brokers/plugins/` 分别声明数据接口与券商接口。`platform_catalog()` 是两者的兼容合并视图；旧 `platforms/plugins/` 不参与默认装配。登记文件会执行受信任的本地 Python 模块，并非安全沙箱。

`framework/data_requirements.py` 定义供应商无关的 `DataRequirements`：市场、资产类型、股票范围、字段、频率和历史长度。策略登记的 `data_requirements` 加上构造参数与 `history_requirements` 生成需求；数据适配器通过 `for_request(request)` 接收并校验。供应商不决定当前用科技股还是全行业，也不执行策略排名和仓位规则。

Massive 统一实现两种股票输入契约，按需求选择股票和字段，不需要财报的策略不会调用财报端点。供应商基础缓存共享，快照和 latest 按需求摘要隔离，切换策略会清除旧选择与预览。新格式 `current_us_equity_request_v1` 保存完整需求；加载时核对范围、字段和历史长度。行业识别可能先扫描全市场基础资料，只有符合范围的股票继续下载日线和所需财报。Futu 目前仍仅适配科技股契约，原研究格式继续使用。

研究输入记录来源和观察时间，固定禁止直接执行；可执行快照仍需额外的证券、时间和报价校验。Massive 的股票池和价格口径详见 [说明](../data/MASSIVE.md)。

可选 `PortfolioContext` 通过标准契约向策略提供冻结的持仓名单。决策指纹包括这份输入；首次执行在账户检查后冻结订单，同批次恢复继续沿用原始 context。默认无状态策略接口保持兼容。

账户只读查询使用独立的 `account_reader` 类型，不向执行器暴露 Tiger SDK。它与 `broker` 类型不互换，因此查询模块不会被误当成可下单的连接器。

`tiger_paper` 是独立 broker 插件，实现同一个账户与订单接口。它持有 SDK、模拟账号核验、请求白名单、订单号映射和网络错误处理。通用执行器只区分本地模拟时钟和联网模拟时钟，不导入 Tiger。`configs/tiger_paper_config.json` 继承研究配置并选择该插件，框架与策略代码共用。

## Portal 控制层

`ui/src` 只呈现 `/api/state` 返回的模块、参数和能力；不导入 SDK，也不按具体策略或供应商名称分支。`portal/` 负责 HTTP、会话和进程控制；`app/workbench.py` 负责选择、任务和日志；`app/module_registry.py` 读取三类登记文件和实例配置；`app/portal_worker.py` 通过控制适配器执行任务。

- 策略：构造参数和登记元数据生成表单，仍实现固定框架的 `PortfolioStrategy`。
- 数据：`data/controls.py` 承担设置、采集、快照解析；转换成 `SnapshotInput` 后交给框架。
- 券商：`brokers/controls.py` 承担账户检查、绑定校验、状态路径与 session；沿用 `app/assembly.py` 的执行器。
- QC：保留原代码导出、结果导入与实验核验，不随当前数据提供商或券商改变回测引擎。

策略和数据通过 schema 匹配，券商通过市场、资产类别、币种、订单类型、股数类型和有效期能力，以及实际账户环境校验。新模块声明 `control` 和默认实例后自动出现在 Portal；同一接口内增加供应商无需改页面或框架。旧单标的策略、未适配的接口仍可列出，但不能被误装配进组合执行器。详见 [模块接入契约](../portal/README.md)。

每次预览绑定所选策略、数据、券商、实例参数及连接配置的摘要；切换模块或改绑定使预览失效。账户显示与订单账本跟随券商实例，切换本身不建立连接、初始化账户或下单。当前 Portal 仅启用 `paper` 与 `broker_paper`；实盘登记不会获得执行权限。

### 独立后台生命周期

面板控制进程与交易后台进程分开。`portal/controller.py` 在后台停止时仍提供静态页面、会话和启停接口；`portal/runtime.py` 管理后台子进程，检查其进程存活、健康接口和实例标识。运行中的模块 API 转发给独立后台，停用时不接受交易操作。

停止由后台在同一任务锁内检查空闲状态，再正常退出；控制进程确认真实进程退出后才报告已停止。再次开启创建新的服务实例，不恢复预览授权或重放任务。控制进程丢失时通过私有管道和父进程状态检测，已有操作完成后退出；独立进程锁阻止旧后台尚未退出时启动另一份。模块注册、策略、券商、QC 和框架接口保持不变。

## 回测是一种运行方式

```text
同一份策略源码 + 同一份策略参数
              ├→ QuantConnect 平台 → LEAN 历史撮合与报告
              ├→ 本地框架 → 报价回放券商 → 状态与执行记录
              └→ 本地框架 → Tiger 模拟券商 → 券商订单与本地恢复记录
```

QC 的生成文件由框架契约、策略源码和平台适配器自动合成，便于复制到网站。数据读取、历史日历、撮合仍属于 LEAN；没有另外编造一套轻量股票引擎来声称能准确处理全部分红、拆股和停牌。

共享的是策略规则、显式参数、目标限制和决策指纹。费用、撮合、时点和订单状态的实现不同，收益不会因此自动相同。本地纸面执行器不是历史市场回测。

`backtests/engine.py` 与 `app/research.py` 服务单标的总回报序列；它们不能直接接受多股票组合策略。QC 适配与报告解析维护在 `backtests/quantconnect/`，可复制单文件继续输出到原 `platforms/quantconnect/main.py`。旧 `framework.backtest`、`framework.experiments`、`platforms.data.*` 和 `platforms.brokers.*` 只保留兼容别名，没有复制运行状态或另建账户账本。

## 运行与恢复

本地先预览决策，再创建/恢复专用模拟账户并执行。订单意图先写 SQLite，再提交；每笔前检查现金、费用、报价和仓位。卖单确认后才买入，未知/部分成交/拒单会阻止后续流程，重启先核对既有订单。

数据层明确标记缺失数据，不能把故障转换为空选股清仓。一个账户只使用一个状态目录；缺失账本不得自动重建。运行同一交易日时修改策略或参数会被识别为另一批决策，不能覆盖旧批次。

Futu/moomoo 已提供独立 live 入口，要求明确账户和执行激活；模拟与实盘共享订单接口、风控和恢复逻辑。实盘的联网验收、结算、公司行动及持续运行仍待完善，策略源码保持独立。

Tiger 模拟执行是一轮一轮运行的：未完成订单暂停后续交易，恢复查询不重复发送。没有常驻轮询服务、行情订阅或已取消批次的自动处置。凭据和账户状态分别固定在 `secrets/tiger_paper/`、`runs/tiger-paper/`，不会被打包进 QC 或提交 Git。

Futu 与 moomoo 各有 paper/live 平台入口，共用 `platforms/opend.py` 和 `brokers/opend_broker.py` 的协议转换与订单恢复逻辑。连接配置和 SQLite 账本按平台与环境隔离；绑定包含平台、环境、登录用户和账号，旧 paper 指纹兼容保留。策略源码与 `framework/` 没有引入这些 SDK。行情检查登记为 `market_reader`，不能冒充策略要求的完整 `snapshot_data`。详见 [OpenD 接入](../platforms/opend.md)。

## 参数与版本

主配置 `configs/portfolio_config.json` 供组合模式和 QC 导出共用。研究日期、资金、成本、选股参数、目标限额可查看、冻结和比较。每次导出保存独立 manifest 和源码校验值，不覆盖旧实验。

每个决策保存输入指纹、策略源码与框架指纹、有效参数（包括默认值）、目标组合。数据提供者/券商的连接参数不打包进云端回测文件。

QC 结果格式由平台模块解析；框架研究模块只保存归一化指标和原始证据。导出 manifest 保持 `exported_not_run`，每次导入另建结果目录；汇总明确区分失败、未完成、完成情况未知及文件声称完成。文件哈希检查用于发现改动，不构成来源认证或盈利证明。

## 后续验证顺序

Massive 采集使用 `framework/collection.py` 的可选纯函数契约。策略提供价格初筛、排名优先级及排名前缀完成条件；供应商负责批量日线、资料获取、复权和校验。MOM8 的 `price_score` 同时用于采集初筛和最终选股，避免在数据源复制一套策略规则；无此钩子的策略仍可要求完整候选资料。原始行情按日期跨策略复用，研究快照按范围、字段、历史及策略采集规则指纹隔离。资料前缀及覆盖信息明确记录，研究文件不能提交券商订单。

基准回测复现 → 明确假设后比较策略部件 → 冻结规则并验证独立区间 → 券商模拟盘核对信号和订单 → 单独准备小额实盘。

回测次数、文件数量和框架复杂程度都不作为上线结论。暂停新单、撤销挂单和清仓是三种不同操作。
# 模拟订单准备

Massive 的原始文件继续标为研究数据。工作台的 `prepare` 操作在组合层调用数据模块的 `paper_signal` 和券商模块的只读持仓、报价接口，按实际持仓重新选股，并保存独立的 `paper_order_preparation_v1` 订单预览。它明确记录 `current_observation`，不会把今天观察的资料倒填成历史时点数据。覆盖缺失仍展示，未通过资料验证的证券不会参与本轮模拟选股。

目前 Futu 与 moomoo 模拟模块提供这项能力。股票行情连接使用默认 `SecurityFirm.NONE`，交易连接仍保留各自的券商、用户和 SIMULATE 账户绑定。报价保留券商原始时间戳；服务端时间仅用于有界的本机时钟校准，偏差超过两分钟时阻止执行。休市、过期行情、未完成委托、信号日期不一致都显示具体原因。

订单预览列出整数股数量、限价和金额，按已有单笔上限拆分，价格取合法的美股分币档位。确认执行会复核原始信号哈希、配置、预览期限、现金和完整持仓，数量和限价不会暗中变化。已接受的委托最多查询十秒确认成交；不明、拒绝、超时或部分成交均暂停后续委托，不自动重发或撤单。原始文件回放和 QC 的历史信息时间限制保持默认严格。

## 模块替换与故障隔离

登记目录逐文件检查。格式错误、重复编号和缺少依赖的未使用插件显示为不可用，不阻断其他模块列表；重复编号不会任意选一份生效。必需模块加载失败仍阻止预览和执行，不会自动换策略、数据源或账户。账户只读检查只绑定券商配置，数据设置只绑定所选数据模块，避免无关插件妨碍修复。

`app/operations.py` 定义固定操作和上下文范围；`app/readiness.py` 给出每项操作的 enabled、blockers、message 和 next_action。Portal 按该结果显示按钮和原因，服务在接收操作时重新计算相同条件；worker 仍复核账户环境、数据、报价、数量、限额和授权摘要。页面可用状态不会代替提交前检查。账户核验失效、预览报价到期、研究数据、缺失配置均有具体原因。

订单能力在 `framework/order_capabilities.py` 定义，数据接入返回已验证的 OrderRequirements。券商的 `control.order_capabilities` 声明支持的 market、asset_class、currency、order_type、quantity_type、time_in_force。缺失或不匹配时拒绝准备与执行；不再把策略输入 schema 列表放进券商。当前实现仍为美股 USD 整股 DAY 限价订单，新资产必须实现真实的数据解析和订单能力，不能仅改登记文字。

Portal 不读取 SQLite 表，也不导入具体券商。`framework/journal_reader.py` 提供只读订单视图；`app/broker_authorization.py` 管理授权生命周期；`app/credential_store.py` 保存唯一活动授权；`app/origins.py` 提供与网页无关的回调地址校验。旧导入路径仅保留兼容别名。

日常命令行使用 `python bot.py workbench <操作>`，作为当前工作台的 API 客户端，与网页共享模块选择、任务锁、预览和账户核验。默认账户查询同样进入工作台；不存在隐含 Tiger 选择。旧的显式配置研究/接入函数仍供测试与已有集成使用，`broker-paper` 必须显式指定配置，不读取网页预览。数据配置与采集命令使用当前工作台模块，不再另开一套供应商分支。
